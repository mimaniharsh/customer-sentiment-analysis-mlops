# SETUP GUIDE — Sentient Intelligence Platform
## GitHub Codespaces → Local Dev → GitHub Actions Workflows

---

## PART 1: Upload to GitHub & Open in Codespaces

### Step 1 — Create a new GitHub repository

1. Go to https://github.com/new
2. Name it `sentient-platform` (or anything you like)
3. Set it to **Private**
4. Do **NOT** initialize with README, .gitignore, or license (we have all of these)
5. Click **Create repository**

---

### Step 2 — Upload the project

On your local machine, unzip the downloaded `sentient-platform.zip`, then:

```bash
# Unzip
unzip sentient-platform.zip
cd sentient-platform

# Initialize git
git init
git branch -M main

# Add your GitHub repo as origin (replace YOUR_USERNAME)
git remote add origin https://github.com/YOUR_USERNAME/sentient-platform.git

# Stage and commit everything
git add .
git commit -m "feat: initial commit — Sentient Intelligence Platform v2"

# Push
git push -u origin main
```

> **Verify:** On GitHub, check that `.env` does NOT appear in the file list.
> Only `.env.example` should be visible. The `.gitignore` protects your real `.env`.

---

### Step 3 — Open in GitHub Codespaces

1. On your GitHub repo page, click the green **`< > Code`** button
2. Click the **Codespaces** tab
3. Click **Create codespace on main**
4. Wait ~3 minutes for the container to build and the `setup.sh` script to run automatically

When it opens, you'll see VS Code in your browser. The terminal will show the setup completing.

---

## PART 2: Configure Secrets in the Codespace

### Step 4 — Add your AWS credentials to .env

In the Codespace terminal:

```bash
# The setup script already created .env from .env.example
# Now open it and add your credentials
code .env
```

Fill in **at minimum** these lines with your real values:

```env
# Your existing AWS credentials — paste YOUR values here (from your .env or AWS console)
AWS_ACCESS_KEY_ID=<your-access-key-id>
AWS_SECRET_ACCESS_KEY=<your-secret-access-key>
AWS_REGION=ap-south-1

# Your existing SageMaker endpoint
SAGEMAKER_ENDPOINT_NAME=customer-sentiment-analysis-mlops-endpoint

# S3 bucket from your original project
S3_BUCKET=your-s3-bucket-name
S3_PROJECT_PREFIX=customer-sentiment-analysis-mlops

# These were auto-generated by setup.sh — leave as-is
APP_SECRET_KEY=<already filled in>
JWT_SECRET_KEY=<already filled in>
```

Save the file. **It will never be committed** — `.gitignore` blocks it.

## PART 4: Configure GitHub Actions for CI/CD and ML Workflows

You need to add secrets and variables in your GitHub repository settings.

### Step 7 — Add GitHub Actions Variables (non-secret config)

Go to: **GitHub repo → Settings → Secrets and variables → Actions → Variables tab**

Click **New repository variable** for each:

| Variable Name | Value | Description |
|---|---|---|
| `AWS_REGION` | `ap-south-1` | Your AWS region |
| `S3_BUCKET` | `your-s3-bucket-name` | Your S3 bucket |
| `PROJECT_NAME` | `customer-sentiment-analysis-mlops` | ML project prefix |
| `SAGEMAKER_ENDPOINT_NAME` | `customer-sentiment-analysis-mlops-endpoint` | Endpoint name |
| `ECR_REGISTRY` | `123456789.dkr.ecr.ap-south-1.amazonaws.com` | Your ECR registry URL |
| `ECS_CLUSTER` | `sentient-cluster` | ECS cluster name (for deploy workflow) |
| `API_PUBLIC_URL` | `https://your-api-domain.com` | Public API URL (for deploy workflow) |

---

### Step 8 — Add GitHub Actions Secrets (sensitive values)

Go to: **GitHub repo → Settings → Secrets and variables → Actions → Secrets tab**

Click **New repository secret** for each:

| Secret Name | Value | Where to find it |
|---|---|---|
| `AWS_ROLE_ARN` | `arn:aws:iam::ACCOUNT_ID:role/GitHubActionsRole` | Your AWS IAM console |
| `SAGEMAKER_ROLE_ARN` | `arn:aws:iam::ACCOUNT_ID:role/SageMakerExecutionRole` | Your AWS IAM console |
| `AWS_DEPLOY_ROLE_ARN` | `arn:aws:iam::ACCOUNT_ID:role/GitHubDeployRole` | Your AWS IAM console |
| `KAGGLE_USERNAME` | `your-kaggle-username` | Your Kaggle profile |
| `KAGGLE_KEY` | `your-kaggle-api-key` | Kaggle → Account → API |

> **Important about `AWS_ROLE_ARN`:** The CI/CD workflows use **GitHub OIDC** — they assume an IAM role without any static key. You need to create this IAM role in your AWS account. See Step 9 below.

---

### Step 9 — Create the GitHub OIDC IAM Role in AWS (one-time setup)

This is what allows GitHub Actions to call AWS without any stored access keys.

**In AWS IAM Console:**

1. Go to **IAM → Identity providers → Add provider**
2. Choose **OpenID Connect**
3. Provider URL: `https://token.actions.githubusercontent.com`
4. Audience: `sts.amazonaws.com`
5. Click **Add provider**

**Create the role:**

1. Go to **IAM → Roles → Create role**
2. Trusted entity type: **Web identity**
3. Identity provider: `token.actions.githubusercontent.com`
4. Audience: `sts.amazonaws.com`
5. Add condition: `token.actions.githubusercontent.com:sub` = `repo:YOUR_USERNAME/sentient-platform:*`
6. Attach policies:
   - `AmazonSageMakerFullAccess`
   - `AmazonS3FullAccess`
   - `AmazonEC2ContainerRegistryFullAccess`
   - `AmazonECS_FullAccess`
7. Name it `GitHubActionsRole`
8. Copy the ARN → use it as `AWS_ROLE_ARN` in Step 8

## PART 5: Run the GitHub Actions Workflows

### Step 10 — Run the CI workflow (automatic)

The CI workflow (`01-ci.yml`) runs **automatically** on every push. To trigger it now:

```bash
# Make a small change and push
echo "# test" >> docs/notes.md
git add .
git commit -m "test: trigger CI"
git push
```

Go to: **GitHub repo → Actions → CI — Build, Lint, Test, Scan**

You'll see:
1. ✅ Secret Scanning (Gitleaks scans for any leaked credentials)
2. ✅ Python lint & tests (ruff + pytest with mocked ML pipeline)
3. ✅ Frontend build (Next.js build validation)
4. ✅ Docker build validation

---

### Step 11 — Run the ML Training workflow

Go to: **GitHub repo → Actions → ML — Train & Deploy SageMaker Model**

1. Click **Run workflow**
2. Set parameters:
   - Epochs: `10` (default)
   - Batch size: `32` (default)
   - Deploy after train: `true`
3. Click **Run workflow**

**What happens:**
1. Downloads Twitter Airline Sentiment dataset from Kaggle → S3
2. Preprocesses and splits data
3. Packages your training script and uploads to S3
4. Launches `ml.g4dn.xlarge` GPU training job on SageMaker (~30–45 min)
5. Waits for completion, fetches model artifact URI
6. Deploys trained model to your endpoint `customer-sentiment-analysis-mlops-endpoint`

Monitor progress in: **Actions → ML — Train & Deploy SageMaker Model → running job → logs**

---

### Step 12 — Run the Deploy workflow (after ECR/ECS setup)

Once you have ECR and ECS set up:

Go to: **GitHub repo → Actions → CD — Deploy to Production**

1. Click **Run workflow**
2. Choose environment: `staging` or `production`
3. Click **Run workflow**

This builds Docker images, pushes to ECR, and deploys to ECS.

## PART 7: Troubleshooting

### "Prediction failed: ML endpoint unavailable"
- Your SageMaker endpoint is not InService
- Check: `aws sagemaker describe-endpoint --endpoint-name customer-sentiment-analysis-mlops-endpoint --region ap-south-1`
- If it shows "OutOfService" or "Failed", run the ML training workflow (Step 11) to deploy a fresh model

### "Cannot start in production without Secrets Manager"
- You have `APP_ENV=production` but haven't set up Secrets Manager
- Either set `APP_ENV=development` in `.env`, or run `scripts/setup-secrets-manager.sh`

### "Missing required configuration" on startup
- Open `.env` and ensure `APP_SECRET_KEY` and `JWT_SECRET_KEY` are filled in
- Run: `openssl rand -hex 32` twice to generate them

### Docker compose fails to start
```bash
# Check which service failed
docker compose logs api
docker compose logs web

# Restart a specific service
docker compose restart api
```

### GitHub Actions workflow fails at "Configure AWS credentials"
- Ensure `AWS_ROLE_ARN` secret is set (Step 8)
- Ensure the OIDC identity provider is configured in your AWS account (Step 9)
- The role's trust policy must include your exact repo: `repo:YOUR_USERNAME/sentient-platform:*`

### Port forwarding not working in Codespaces
- Go to the **Ports** tab in the VS Code bottom panel
- Right-click port 3000 → **Port Visibility → Public** (for sharing)
- Or click the globe icon next to the port to open in browser
